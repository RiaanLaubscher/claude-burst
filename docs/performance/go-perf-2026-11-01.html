Caveats

  • Load during runs: the machine was shared (load average 6 to 28 on 10 cores, mostly a Virtualization process and Playwright Chromium, plus other projects queued on rlock). Every kept change was decided by an interleaved ab.sh run (n=10), not by the sequential baseline-vs-optimized rows.
  • Baseline vs optimized sec/op for CompactionStrategies reads as ~ (125ms +-32% vs 159ms +-28%, p=0.143): noise from load. Its deciding A/B (step 4) was 106.6ms -> 97.8ms, p=0.075. The change is kept for memory: B/op -81%, allocs/op -90%.
  • Untracked edits appeared in the working tree during the pass that are not part of these changes (go fix style modernisations in metrics.go, repo.go and two tests, and a dropped toolchain line in go.mod). "Before" binaries were built from a clean git worktree at HEAD plus the benchmark files and the corrected go.mod.
  • Benchmarks use a synthetic history (170,000 events, 3,800 sessions, 14 days) shaped like this machine's (162,000 events, 3,809 sessions) and a synthetic projects directory (32 dirs x 118 transcripts, as on this machine: 3,774 files). Absolute numbers on the live gateway will differ.
  • ColdLoad (a first parse of a 52MB history, 216MiB allocated) is unchanged. It is paid once per file after a gateway start or a rotation, and is the largest remaining single allocation.
  • PGO was excluded at the user's request.
  • betteralign findings were not applied: the benefit is GC scan-work only, Event's field order is its JSON output order, and the held store already packs events by hand (pack.go).
